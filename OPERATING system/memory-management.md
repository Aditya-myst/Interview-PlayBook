# 07 — Memory Management

## How the OS Allocates and Tracks Memory

---

### The Memory Hierarchy

```
Fastest                                          Slowest
┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐
│Cache │  │ RAM  │  │ SSD  │  │ HDD  │  │Tape  │
│ ~1ns │  │~100ns│  │ ~1ms │  │~10ms│  │ ~1s  │
│~KB-MB│  │~GB   │  │~TB   │  │~TB   │  │~PB   │
└──────┘  └──────┘  └──────┘  └──────┘  └──────┘
```

**The OS manages RAM** — the primary memory that processes use.

---

### Memory Management Goals

1. **Allocation:** Give each process the memory it needs
2. **Protection:** Processes can't access each other's memory
3. **Sharing:** Allow controlled sharing (shared libraries)
4. **Relocation:** Programs can be loaded at any address
5. **Efficient use:** Minimize wasted memory

---

### Memory Allocation Strategies

#### Fixed Partitioning

Memory divided into fixed-size partitions. Each partition holds one process.

```
┌─────────────────────────┐
│  OS (Kernel)            │
├─────────────────────────┤
│  Partition 1 (2MB)      │  Process A (1.5MB) → 0.5MB wasted (internal fragmentation)
├─────────────────────────┤
│  Partition 2 (4MB)      │  Process B (3MB) → 1MB wasted
├─────────────────────────┤
│  Partition 3 (4MB)      │  Empty
├─────────────────────────┤
│  Partition 4 (8MB)      │  Process C (8MB) → Fits exactly
└─────────────────────────┘
```

**Problem:** Internal fragmentation (wasted space within partition).

#### Dynamic Partitioning

Partitions created on demand, sized to fit the process.

```
Before:                    After allocating B (3MB):
┌──────────────────┐       ┌──────────────────┐
│ OS               │       │ OS               │
├──────────────────┤       ├──────────────────┤
│ Process A (2MB)  │       │ Process A (2MB)  │
├──────────────────┤       ├──────────────────┤
│                  │       │ Process B (3MB)  │
│ Free (6MB)       │       ├──────────────────┤
│                  │       │ Free (3MB)       │
└──────────────────┘       └──────────────────┘
```

**Allocation Strategies:**

| Strategy | Description | Pros | Cons |
|----------|-------------|------|------|
| **First Fit** | First hole that fits | Fast | External fragmentation |
| **Best Fit** | Smallest hole that fits | Less fragmentation | Slow, small fragments |
| **Worst Fit** | Largest hole | Larger remaining hole | Slow, fragmentation |
| **Next Fit** | First fit from last position | Distributes evenly | Fragmentation |

**Problem:** External fragmentation (free memory scattered in small pieces).

### Compaction

Move processes to consolidate free memory.

```
Before compaction:          After compaction:
┌──────────┐               ┌──────────┐
│ Process A │               │ Process A │
├──────────┤               ├──────────┤
│ Free 1MB  │               │ Process B │
├──────────┤               ├──────────┤
│ Process B │               │ Process C │
├──────────┤               ├──────────┤
│ Free 2MB  │               │ Free 6MB  │
├──────────┤               └──────────┘
│ Process C │
├──────────┤
│ Free 3MB  │
└──────────┘
```

**Cost:** Expensive—requires moving processes while they're running.

### Address Binding

When do addresses get assigned?

| Binding | When | Example |
|---------|------|---------|
| **Compile Time** | At compilation | Absolute code (must know location at compile time) |
| **Load Time** | When loading into memory | Relocatable code |
| **Execution Time** | During runtime | Modern OS (uses hardware support) |

```
Source Code → Compiler → Object Module → Linker → Load Module → Loader → In Memory
                ↓              ↓            ↓           ↓
           Addresses      Relocatable   External    Final
           generated      addresses     references  addresses
                                          resolved   assigned
```

### Logical vs Physical Address

| Type | Description | Generated By |
|------|-------------|--------------|
| **Logical (Virtual)** | Address generated by CPU | Program |
| **Physical** | Actual address in RAM | Memory Management Unit (MMU) |

```
CPU generates logical address
        │
        ▼
┌─────────────┐
│     MMU     │  Maps logical → physical
└──────┬──────┘
       │
       ▼
Physical address in RAM
```

**Why?** Programs use logical addresses. The OS + MMU translate to physical. This enables:
- Relocation (program can be anywhere in memory)
- Protection (can't access other processes' memory)
- Virtual memory (more memory than physically available)

---

### Memory Protection

Each process has a **base register** (smallest legal address) and **limit register** (size of address space).

```
CPU generates address
        │
        ▼
┌───────────────────┐
│ Is address >= base │──No──→ Trap (addressing error)
│ AND                │
│ Is address < base  │
│    + limit?        │──No──→ Trap (addressing error)
└────────┬──────────┘
         │ Yes
         ▼
    Access memory
```

**Hardware support:** Memory Management Unit (MMU) checks every memory access.

### Swapping

Temporarily move processes out of memory to disk (backing store), then bring them back.

```
Memory:                          Disk (Backing Store):
┌──────────────────┐            ┌──────────────────┐
│ OS               │            │ Process C (swapped│
├──────────────────┤   swap     │ out)              │
│ Process A        │◄──────────│                   │
├──────────────────┤            └──────────────────┘
│ Process B        │
└──────────────────┘
```

**Swap time** = Transfer time + Seek time + Latency

**Modern systems:** Use swapping + virtual memory together. Pages swapped, not entire processes.

### Memory Allocation in Practice

#### Stack Memory
- Automatic allocation/deallocation
- Local variables, function parameters
- LIFO order
- Fast (just move stack pointer)
- Limited size

#### Heap Memory
- Manual allocation (malloc/new) and deallocation (free/delete)
- Dynamic data structures
- Slower than stack
- Can grow/shrink

```
High Address ┌─────────────────┐
             │ Stack           │ ← Grows downward
             │ (local vars)    │
             ├─────────────────┤
             │ ↓               │
             │ Free Space      │
             │ ↑               │
             ├─────────────────┤
             │ Heap            │ ← Grows upward
             │ (dynamic alloc) │
             ├─────────────────┤
             │ BSS (uninit)    │
             ├─────────────────┤
             │ Data (init)     │
             ├─────────────────┤
             │ Text (code)     │
Low Address  └─────────────────┘
```

### Garbage Collection

Automatic memory management. The system reclaims memory that's no longer referenced.

| Technique | Description | Used By |
|-----------|-------------|---------|
| **Reference Counting** | Count references to each object | Python, Swift |
| **Mark and Sweep** | Mark reachable objects, sweep unmarked | Java, Go |
| **Copying GC** | Copy live objects to new space | JVM young generation |
| **Generational GC** | Separate spaces for young/old objects | JVM, .NET |

### Interview Questions

**Q: What's the difference between internal and external fragmentation?**

A: "Internal fragmentation is wasted space within an allocated block—the process doesn't fully use the partition. External fragmentation is free memory scattered in small, non-contiguous pieces—enough total free memory exists but not in one contiguous block. Fixed partitioning causes internal fragmentation; dynamic partitioning causes external fragmentation."

**Q: What's the difference between logical and physical addresses?**

A: "Logical (virtual) addresses are generated by the CPU during program execution. Physical addresses are the actual locations in RAM. The MMU translates logical to physical addresses using page tables or base/limit registers. This indirection enables relocation, protection, and virtual memory."

**Q: What's swapping?**

A: "Swapping temporarily moves an entire process from memory to disk (backing store) and brings it back later. This allows more processes than can fit in memory simultaneously. The cost is the time to transfer the process to/from disk. Modern systems use paging (swapping individual pages) instead of whole-process swapping."

**Q: Explain the memory layout of a C program.**

A: "From low to high: Text segment (executable code, read-only), Data segment (initialized global/static variables), BSS (uninitialized globals, zero-initialized), Heap (dynamic memory, grows upward), and Stack (local variables, function frames, grows downward). The heap and stack grow toward each other, with free space in between."

**Q: What's the difference between stack and heap memory?**

A: "Stack: automatic allocation, local variables, LIFO, fast, limited size. Heap: manual allocation (malloc/new), dynamic data, slower, larger. Stack is managed by the compiler (push/pop on function calls). Heap is managed by the programmer (or garbage collector). Stack overflow occurs with deep recursion; heap overflow with memory leaks."
